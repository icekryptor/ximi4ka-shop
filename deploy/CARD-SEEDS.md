# Данные карточек товаров: одноразовые `apply-*` скрипты

Состав, характеристики и описания некоторых карточек вносятся в БД не миграциями и не при
деплое, а отдельными одноразовыми скриптами. **Мёрж в `main` выкатывает только код: данные
в прод-БД появятся лишь после запуска скрипта на сервере.** Так «Состав» мини-химички и
электрохимички оказался в `main`, но на витрине был пуст, пока скрипты не запустили (11.10.2026).

Общий ранбук сервера — [`README.md`](README.md); запуск сидов в контейнере описан в
[`SEO-LAUNCH.md`](SEO-LAUNCH.md), раздел «Как запускать в контейнере». Ходить на прод-сервер и
в прод-БД — только по явной команде владельца в чате.

## Скрипты

| npm-скрипт (ноутбук)            | Команда в контейнере                                   | Карточка (slug)          | Что пишет                                                                      |
| ------------------------------- | ------------------------------------------------------ | ------------------------ | ------------------------------------------------------------------------------ |
| `apply:mini-himichka-card`      | `node api/dist/seeds/apply-mini-himichka-card.js`      | `mini-himichka`          | блоки «Состав» и «Характеристики»                                              |
| `apply:electro-card`            | `node api/dist/seeds/apply-electro-card.js`            | `elektrohimichka`        | блоки «Состав» и «Характеристики»                                              |
| `apply:himichka-30-composition` | `node api/dist/seeds/apply-himichka-30-composition.js` | `himichka-30`            | блоки «Состав» и «Характеристики»                                              |
| `apply:oge-card`                | `node api/dist/seeds/apply-oge-card.js`                | `bolshoi-nabor-dlya-oge` | **фото** (`product_images`), короткое и мета-описание, подробное описание, FAQ |

Исходники — `api/src/seeds/apply-*.ts`, данные наборов — `api/src/seeds/_lib/*-card.ts`.
Что нового в составе набора — правится там, затем мёрж, затем повторный запуск скрипта.

Свойства всех четырёх:

- **Идемпотентны.** Прежние блоки «Состав» и «Характеристики» вырезаются и заменяются свежими,
  дублей нет. Остальное описание, цена, SEO-поля не трогаются (`apply:oge-card` дополнительно
  заменяет фото, короткое и мета-описание, смотрите «Осторожно» ниже).
- **`--dry-run`** читает БД, печатает значение «до» и ничего не пишет.
- **В боевом режиме тоже печатают значение «до»** (JSON в логе): сохраните вывод, по нему
  делается откат.
- Нет карточки с таким slug — скрипт падает с ошибкой «Товар … не найден в БД», запись
  откатывается (всё в одной транзакции).
- Точка входа — `main()` на верхнем уровне файла, `tsx` и `api/data` в контейнере не нужны.

## Запуск на проде

```bash
cd /opt/ximishop/app
C="docker compose --env-file deploy/web.env -f deploy/docker-compose.yml"

# 1. Dry-run: карточка найдена, что лежит сейчас (вывод сохранить для отката)
$C exec -T ximishop-api node api/dist/seeds/apply-electro-card.js --dry-run 2>&1 | tee -a /root/backups/card-seeds.log

# 2. Запись
$C exec -T ximishop-api node api/dist/seeds/apply-electro-card.js 2>&1 | tee -a /root/backups/card-seeds.log

# 3. Проверка в БД: блоки на месте (ожидаем t)
docker exec -i supabase-db psql -U supabase_admin -d ximi4ka_shop -At \
  -c "SELECT slug, jsonb_array_length(long_description_blocks),
             long_description_blocks::text LIKE '%Состав%'
         AND long_description_blocks::text LIKE '%Характеристики%'
        FROM products WHERE slug = 'elektrohimichka';"
```

Для другой карточки меняется только имя файла в `node api/dist/seeds/apply-….js`
(slug — в таблице выше). Скрипт запускается после автодеплоя: пока контейнер не пересоздан,
нового файла в `api/dist/seeds/` ещё нет (`ls api/dist/seeds | grep card`).

### Проверка на витрине

Страницы кешируются на минуту (`s-maxage=60`, ISR), так что обновление видно со следующего
запроса:

```bash
curl -s https://ximi4ka.ru/product/elektrohimichka | grep -o 'Размер коробки\|Реактивов в наборе' | sort | uniq -c
```

Адрес карточки — `/product/<slug>` (не `/catalog/<slug>`: там 404).

## Откат

В логе боевого запуска (и dry-run) есть поле `before.longDescriptionBlocks` — прежнее значение
колонки `products.long_description_blocks`. Вернуть его:

```bash
$P -c "UPDATE products SET long_description_blocks = '<JSON из лога>'::jsonb WHERE slug = '<slug>';"
```

где `P="docker exec -i supabase-db psql -U supabase_admin -d ximi4ka_shop"`. Для
`apply:oge-card` в логе дополнительно — прежние фото, короткое и мета-описание; их возврат вручную из лога.

## Осторожно

- `apply:oge-card` заменяет фото в `product_images`, короткое и мета-описание, а не только блоки. Перед боевым
  запуском — dry-run и сверка, что новые фото действительно нужны.
- После правки данных в `_lib/*-card.ts` и мёржа **не забыть повторный запуск**: код на
  проде обновится, значения в БД — нет.
- Правка вручную в админке той же карточки при повторном запуске скрипта перезапишет только
  блоки «Состав» и «Характеристики» (определяются по заголовкам `<h3>Состав</h3>` и
  `<h3>Характеристики</h3>` в начале абзаца); остальные блоки сохраняются.
