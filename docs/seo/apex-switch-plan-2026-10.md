## B. День переключения

1. **Caddy, апекс и `www`.** Добавить `deploy/Caddyfile.apex.snippet`, `caddy validate`, `caddy reload`. Блок `new.ximi4ka.ru` не трогать.
2. **DNS.** Поменять A-записи апекса и `www` на IP сервера (тот же, что у `new.ximi4ka.ru`, см. `deploy/README.md`). Сертификат Caddy выпустит
   при первом обращении, в первые минуты возможна ошибка TLS.
3. **Проверка апекса:** `curl -sI https://ximi4ka.ru`; `/robots.txt` по-прежнему `Disallow: /`; открываются `/`, `/policy`, `/catalog`, `/blog`;
   работают редиректы `/policy2`, `/catalog/kits`, `/aboutus`; `/experiment` — 404; `https://www.ximi4ka.ru/x` — 301 на апекс.
4. **Пересборка web** с `NEXT_PUBLIC_SITE_URL=https://ximi4ka.ru` (переменная вшивается в сборку) и правка `deploy/app.env`: `WEB_ORIGIN`, `TBANK_*`. `WEB_ORIGIN`
   в API — одна строка (CORS `origin`, `api/src/app.ts`): после правки запросы со страниц `new.ximi4ka.ru` по CORS отвалятся, поэтому шаг 5 делать сразу.
   **Единый вход learn.** Learn ходит за кодом на адрес из своей `XIMI4KA_SSO_URL` (по умолчанию `new.ximi4ka.ru`). Поставить там `https://ximi4ka.ru`,
   передеплоить learn и пройти вход на `learn.ximi4ka.ru` через ximi4ka ID: кнопка ведёт на `ximi4ka.ru/account/login`, после входа возвращает на learn уже
   залогиненным. Сессия магазина хранится в куке без домена, поэтому вошедшие на `new.` войдут заново, один раз.
5. **`new.ximi4ka.ru` → апекс, 301.** Заменить блок `new.ximi4ka.ru` на `deploy/Caddyfile.new-redirect.snippet` (старый блок удалить). Нужен, потому
   что `robots.txt` общий в БД: открытый, он сделал бы `new.` полным дублем. Вебхуки Т-Кассы (`/api/webhooks/*`) и бота входа (`/api/telegram/*`) остаются проксируемыми,
   как и `POST /api/account/sso/token` (обмен кода входа learn: по 301 POST превращается в GET и вход ломается, если learn ещё смотрит на `new.`).
   После `reload` повторить вход на learn через ximi4ka ID.
6. **Т-Касса и Telegram-бот.** В кабинете Т-Кассы поменять notification, success и fail URL на апекс; тестовый платёж: вебхук отвечает 200, заказ в
   админке меняет статус, карточка заказа приходит в Telegram. Вебхук бота входа перерегистрировать на апекс (если бот не в режиме polling):
   `docker compose exec ximishop-api node api/dist/scripts/telegram-set-webhook.js` (адрес берётся из `WEB_ORIGIN`, уже на апексе после шага 4),
   затем `curl -s https://ximi4ka.ru/api/health/telegram` и тестовый вход в кабинет. После этого `handle` с вебхуками в блоке `new.` можно убрать;
   путь `/api/account/sso/token` из него убирать только когда `XIMI4KA_SSO_URL` у learn на апексе и вход на learn проверен.
7. **Открыть сайт для индексации.** В админке заменить `robots.txt` на текст из `deploy/README.md`. Проверка: `curl -s https://ximi4ka.ru/robots.txt`
   (одна строка `Sitemap:`), `/sitemap.xml` и canonical на апексе указывают на `https://ximi4ka.ru`.
8. **Вебмастер и GSC:** «Анализ robots.txt», отправить sitemap, «Переобход» главной, каталога и статей. Подключить счётчик Метрики 113445304 в админке.

**Откат.** До шага 7: вернуть старые A-записи апекса и `www` (из A5), TTL до часа. Если robots уже открыт, сначала вернуть
`User-agent: *` + `Disallow: /`, потом DNS. Блок `new.ximi4ka.ru` вернуть из `Caddyfile.bak-*`.
