# Яндекс Пэй и Сплит на сайте — дизайн

Дата: 2026-10-24, упрощён 2026-10-25. Ветка: `claude/yandex-pay-split-integration-72a27a`.

Продолжает незавершённую работу от 11.10.2026 (worktree `jolly-panini-f53f95`, ветка `claude/yandex-pay-integration-a0e6c6`,
не закоммичена, в main её нет). Оттуда берутся адаптер, построитель корзины и вебхук; всё нужное повторено здесь.

**Главный принцип:** новый код стоит рядом с Т-Кассой и не меняет её. `receipt.ts`, `tbank.ts`, вебхук Т-Кассы и выбор
провайдера по `PAYMENT_PROVIDER` остаются как есть.

## Цель

Покупатель оплачивает заказ через Яндекс Пэй — картой или частями в Сплите — и видит возможность оплатить частями ещё до
чекаута: на карточке товара и в корзине. Т-Касса остаётся основным способом.

Критерии успеха:

- пока Яндекс не включён (нет ключей или выключен `yandexPayEnabled`), прод ведёт себя как сейчас — мёрж ничего не меняет;
- код Т-Кассы не меняется, её тесты проходят без правок;
- в песочнице Яндекса проходит полный цикл и картой, и Сплитом: заказ → форма Яндекса → оплата → статус «оплачен»;
- сумма корзины, переданной Яндексу, равна итогу заказа при промокоде, оптовой скидке и любой доставке;
- потерянный вебхук добирается сверкой;
- скрипт Яндекса не ухудшает заметно INP и FCP карточки товара (замер `tools/perf-lab` до и после);
- ключей нет ни в репозитории, ни в публичных ответах API.

## Принятые решения

| Вопрос            | Решение                                                                                                   |
| ----------------- | --------------------------------------------------------------------------------------------------------- |
| Охват             | Оплата на чекауте плюс плашки Сплита на карточке товара и в корзине (страница и боковая). Каталог — позже |
| Интеграция оплаты | Сервер создаёт заказ в Yandex Pay API, покупатель уходит на `paymentUrl`. Кнопку SDK не используем        |
| Скрипт Яндекса    | `pay.js` только для бейджей и виджета; оплата от него не зависит                                          |
| Чекаут            | Три пункта: «Картой — Т-Банк» (по умолчанию), «Яндекс Пэй», «Сплит — оплата частями» с виджетом графика   |
| Сплит             | Тот же заказ Яндекса с `preferredPaymentMethod: 'SPLIT'`; карта в форме остаётся запасным вариантом       |
| Чеки 54-ФЗ        | Облачная касса (АТОЛ Онлайн или CloudKassir), подключённая в кабинете Яндекса; мы передаём налог позиций  |
| Доставка в ЕАЭС   | Пункты Яндекса скрыты, чекаут для этих стран не меняется                                                  |
| Т-Касса           | Не трогаем                                                                                                |
| Песочница         | Проверяется только локально; на проде сразу боевой режим и один небольшой настоящий платёж                |

## Не входит в задачу

- возвраты, отмена и списание через API Яндекса, двухстадийная оплата, Сплит «при получении»;
- бейджи в каталоге и на главной; брендированная кнопка Яндекс Пэй;
- отметка, чем именно заплатил покупатель (картой или Сплитом): в админке провайдер подписан «Яндекс Пэй»;
- общий реестр провайдеров и рефакторинг слоя оплаты под него (CloudPayments, если дойдёт, сделает это сам);
- отправка чеков нашим сервером: их пробивает касса, подключённая в кабинете Яндекса;
- включение на проде: ключи в `deploy/app.env` и настройки кабинета вносит владелец.

## Конфигурация

| Где     | Что                      | Назначение                                                                           |
| ------- | ------------------------ | ------------------------------------------------------------------------------------ |
| env     | `YANDEX_PAY_MERCHANT_ID` | идентификатор продавца; в песочнице он же ключ API; сверяется с `merchantId` вебхука |
| env     | `YANDEX_PAY_API_KEY`     | ключ API боевого режима (`Authorization: Api-Key …`)                                 |
| админка | `yandexPayEnabled`       | рубильник без перезапуска: выключен → способы Яндекса и плашки скрыты                |
| админка | `yandexPayMode`          | `sandbox` или `production`: хост API и JWKS                                          |

Яндекс **доступен на чекауте**, когда `yandexPayEnabled` включён, задан `YANDEX_PAY_MERCHANT_ID` и:

- в боевом режиме задан `YANDEX_PAY_API_KEY`;
- в песочнице процесс запущен не с `NODE_ENV=production` — песочница никогда не попадает к покупателям на проде.

Вебхук и сверка работают, пока задан `YANDEX_PAY_MERCHANT_ID`, независимо от рубильника — уже созданные заказы досверяются.
`availablePaymentMethods` всегда `['CARD', 'SPLIT']`.

## Сервер

### Модуль `api/src/lib/payments/yandexPay/`

- `config.ts` — `getYandexPayConfig()`: читает env и `getSettings()`, возвращает `{ merchantId, apiKey, mode, baseUrl, jwksUrl }`
  или `null`; `isYandexPayAvailable()` — правило «доступен на чекауте» выше.
- `client.ts`:
  - `createYandexOrder(order, { preferSplit })` — `POST {base}/api/merchant/v1/orders`, `base` = `https://pay.yandex.ru` или
    `https://sandbox.pay.yandex.ru`. Тело: `orderId` (номер заказа), `currencyCode: 'RUB'`, `cart`,
    `availablePaymentMethods: ['CARD','SPLIT']`, `preferredPaymentMethod: 'SPLIT'` при выборе Сплита, `redirectUrls`
    (`onSuccess`, `onError`, `onAbort` — страница заказа с публичным токеном, как у Т-Кассы), `fiscalContact` (email, иначе
    телефон). Ответ `data.paymentUrl` → `{ externalId: orderNumber, paymentUrl }`; сбой логируется с телом ответа и даёт `null`;
  - `getYandexOrderStatus(orderNumber)` — `GET /api/merchant/v1/orders/{orderId}`; `CAPTURED`/`CONFIRMED` → `paid`,
    `FAILED`/`VOIDED` → `failed`, остальное → `pending`, ошибка → `unknown`.
- `cart.ts` — `buildYandexCart(order)`. Позиции и раскидку промокода и копеек берёт из **экспортированных** функций
  `receipt.ts` (`spreadDiscount` и разбиение цены); сам `receipt.ts` меняется только добавлением `export`. Суммы — строки в
  рублях, не больше двух знаков; доставка — отдельная позиция; подарки и обнулённые промокодом позиции пропускаются;
  `productId` уникальны; у каждой позиции `receipt.tax` по таблице Яндекса из `TBANK_RECEIPT_TAX` (`none` → 6). Инвариант:
  сумма позиций равна `order.totalRub`, иначе заказ в Яндекс не отправляется и в лог пишется расхождение.
- `webhook.ts` — `verifyYandexWebhook(rawBody)`: JWT ES256 через `jose` (`createRemoteJWKSet` по `jwksUrl` — кеш и обновление
  при неизвестном `kid` делает библиотека; адрес никогда не берётся из запроса); проверяются `alg`, `exp`, `iat` и
  `merchantId` = `YANDEX_PAY_MERCHANT_ID`. Возвращает `{ orderNumber, status }` или ошибку с `reasonCode`.

### Чекаут API

- `GET /api/public/settings` дополняется полем `yandexPay: { split: true, merchantId?: string } | null`: `null`, если Яндекс
  недоступен; `merchantId` отдаётся **только в боевом режиме** (в песочнице он равен ключу API — без него плашки не рисуются).
- `POST /checkout` принимает необязательный `paymentMethod: 'tbank' | 'yandex_pay' | 'yandex_split'`:
  - нет или `tbank` — как сейчас (`getPaymentProvider()`);
  - `yandex_*`, но Яндекс недоступен — `400`;
  - `yandex_*` при доставке `cdek_manual_cis` — `400`;
  - иначе `payment_provider = 'yandex_pay'`, ссылка из `createYandexOrder`; идемпотентный повтор возвращает сохранённый
    `paymentUrl`, повторный запрос в Яндекс с тем же `orderId` не делается.

### Вебхук `POST /api/webhooks/yandex-pay/v1/webhook`

Яндекс дописывает `/v1/webhook` к Callback URL сам; в кабинете указывается `https://ximi4ka.ru/api/webhooks/yandex-pay`.

- маршрут монтируется в `app.ts` до `express.json` с `express.raw({ type: '*/*', limit: '64kb' })`;
- при незаданном `YANDEX_PAY_MERCHANT_ID` — отказ;
- обрабатывается `ORDER_STATUS_UPDATED`: `CAPTURED`/`CONFIRMED` → `paid`, `FAILED`/`VOIDED` → `failed`, прочие статусы — 200 без
  изменений; неизвестный заказ и заказ с другим `payment_provider` — 200 без изменений;
- ошибка проверки — не-200 с `{ status: 'fail', reasonCode, reason }` (`UNAUTHORIZED`, `TOKEN_EXPIRED`, `OTHER`), успех —
  `200 {"status":"success"}`; повтор события безопасен (`applyPaymentStatus` идемпотентен);
- статус применяется как у Т-Кассы: `applyPaymentStatus(order, status, 'yandex_pay')` и `saveOrderWithStatusEvent` — уведомления,
  выдача материалов и офлайн-конверсии Метрики срабатывают без доработок.

### Сверка

В `reconcilePendingOrders` заказы с `payment_provider = 'yandex_pay'` сверяются через `getYandexOrderStatus`, остальные — как
сейчас. Задача сверки запускается, если работает Т-Касса или задан `YANDEX_PAY_MERCHANT_ID`.

### Типы и админка

- `shared`: `PaymentProvider` дополняется `'yandex_pay'`, актор истории `by` — тоже; тип
  `CheckoutPaymentMethod = 'tbank' | 'yandex_pay' | 'yandex_split'`.
- `orderUi.ts`: подпись «Яндекс Пэй», отличная от «Яндекс (YCP)».

## Витрина

### Плашки Сплита

Клиентский компонент `web/components/payments/SplitBadge.tsx`:

- рисует `<yandex-pay-badge type="bnpl" amount merchant-id source size>` (тип для JSX объявляется вручную, npm-пакета нет);
- подключает `https://pay.yandex.ru/sdk/v1/pay.js` через `next/script` с `id="yandex-pay-sdk"` и `strategy="lazyOnload"`, как
  счётчики в `web/lib/analytics.tsx`;
- ничего не рисует без `merchantId` или при сумме ≤ 0;
- резервирует высоту строки бейджа; если Сплит покупателю недоступен, бейдж скрывает сам Яндекс.

Места: карточка товара под рядом «цена + В корзину» (`product/[slug]/page.tsx:287-293`, `source="item"`, сумма `priceRub`);
страница корзины под «Итого» (`cart/page.tsx:102-103`, `source="cart"`, `totals.totalRub`); боковая корзина под «Итого»
(`CartDrawer.tsx:216-217`), только у открытой. Данные `yandexPay` — из публичных настроек: серверные страницы получают их при
рендере, клиентские — одним запросом.

### Чекаут

Блок «Способ оплаты» в `checkout/page.tsx` перед итогами (около :469), разметка по образцу «Куда доставить»:

- «Картой — Т-Банк» (по умолчанию; если Т-Касса принимает СБП — «Картой или СБП — Т-Банк»), «Яндекс Пэй»,
  «Сплит — оплата частями» с бейджем `source="checkout"` на сумму заказа;
- при выбранном Сплите под пунктом — виджет Ultimate (компонент `SplitWidget.tsx`: `YaPay.createSession` с `merchantId`,
  суммой, `availablePaymentMethods: ['SPLIT']`, `version: 4`; `mountWidget` без своей кнопки; при размонтировании сессия
  уничтожается); без скрипта или без `merchantId` остаётся текст;
- блок виден, только когда `yandexPay` не `null`; иначе чекаут как сейчас;
- при доставке в ЕАЭС пункты Яндекса скрываются, выбор сбрасывается на Т-Банк;
- выбранный способ уходит в `POST /checkout`; на `400` (Яндекс выключили, пока покупатель заполнял форму) — понятное сообщение
  и сброс на Т-Банк;
- логотипы — только официальные из бренд-кита Яндекса; нет файлов — текстовые подписи.

`OrderStatusView`: для неоплаченного заказа Яндекса «Оплатить» ведёт на сохранённую ссылку Яндекса.

## Безопасность

- ключи только в `deploy/app.env` и локальном `api/.env`; в репозитории — плейсхолдеры в `*.env.example`;
- публичные ответы без ключей и без песочничного Merchant ID; песочница на проде недоступна;
- вебхук отказывает при любой неудачной проверке; JWKS только с хостов Яндекса; размер тела ограничен;
- сумма считается только на сервере, клиент передаёт лишь `paymentMethod`;
- перед PR — `/security-review`; ключи, показанные в чате 11.10, перевыпустить после запуска.

## Проверка

1. **Песочница локально.** Владелец вписывает песочничный Merchant ID в локальный `api/.env`. Заказ картой и заказ Сплитом →
   форма песочницы → оплата тестовой картой «Мир» → статус «оплачен» через сверку. Сумма 10 001 ₽ даёт `FAILED`.
2. **Живой вебхук** — по решению владельца: временный туннель (cloudflared) на локальный API и песочничный Callback URL на него;
   иначе вебхук проверяется тестами и первым боевым платежом.
3. **Плашки и скорость** — локально с боевым Merchant ID (он публичный): бейджи, виджет Сплита; замер `tools/perf-lab` до и после.

## Риски и открытые вопросы

- **Категории.** Правила Яндекса запрещают яды, прекурсоры и сильнодействующие вещества; новые реактивы сверять с
  `pay.yandex.ru/docs/ru/forbidden`.
- **Код налога** «без НДС» = 6 по таблице Яндекса; проверить в песочнице.
- **СБП у Т-Кассы** — уточнить, чтобы подпись пункта была правдивой.
- **Акционные тарифы** Яндекса заявлены для «формы заказа»; распространяются ли на оплату по API — вопрос менеджеру.
