# Заказы в Google Таблицу и Telegram — дизайн

**Дата:** 25.09.2026. **Статус:** дизайн согласован по частям, ждёт просмотра спеки.

## 1. Зачем

Команда должна видеть новый заказ сразу, в Telegram, и вести рабочий журнал
заказов в Google Таблице, не заходя в админку. Источник правды остаётся в базе
витрины, таблица и чат её зеркалят.

**Готово, когда:** каждый заказ появляется в таблице и в чате в течение минуты
после оформления, смена статуса обновляет строку и приходит в чат ответом на
карточку, а сбой Google или Telegram не мешает оформить заказ.

## 2. Решения (согласованы 25.09.2026)

| Вопрос          | Решение                                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------- |
| Бот             | Новый бот магазина, пишет напрямую в рабочий чат. От ERP не зависит                                                 |
| Таблица         | Одна строка на заказ, состав одной ячейкой, три колонки суммы                                                       |
| «Отправлен»     | Сейчас — кнопка в админке для оплаченного заказа. Потом — автоматически по статусу СДЭК (этапы 4–5 интеграции СДЭК) |
| События в чат   | Новый заказ — карточка; «оплачен», «отправлен», «отменён», «оплата не прошла» — ответом на карточку                 |
| Доставка данных | Очередь в базе + фоновый обработчик с повторами                                                                     |

## 3. Данные

### Статусы

| В базе            | Для людей        | Кто ставит                                     |
| ----------------- | ---------------- | ---------------------------------------------- |
| `pending`         | создан           | чекаут                                         |
| `paid`            | оплачен          | вебхук Т-Кассы, сверка, кнопка в админке       |
| `shipped` (новый) | отправлен        | кнопка «Отправлен» в админке, только из `paid` |
| `cancelled`       | отменён          | админка                                        |
| `failed`          | оплата не прошла | Т-Касса                                        |

Из `paid` разрешён ровно один переход — в `shipped`. Остальные запреты админки
не меняются.

### Новые поля заказа

- `customer_telegram varchar(33) null` — ник покупателя. На чекауте
  необязательное поле «Telegram». Принимается `username` или `@username`
  (латиница, цифры, `_`, 5–32 символа), хранится как `@username`. Невалидное
  значение — ошибка формы, а не молчаливая обрезка.
- `telegram_message_id bigint null` — id карточки заказа в рабочем чате, на неё
  бот отвечает сменами статуса.

Номер строки в таблице не храним: менеджер может отсортировать таблицу. Строка
ищется по номеру заказа в столбце A.

### Очередь `order_notifications`

| Поле              | Тип                                                                                     | Зачем                 |
| ----------------- | --------------------------------------------------------------------------------------- | --------------------- |
| `id`              | uuid                                                                                    |                       |
| `order_id`        | uuid → orders                                                                           |                       |
| `channel`         | `sheets` \| `telegram`                                                                  |                       |
| `event_key`       | `created` \| `status:paid` \| `status:shipped` \| `status:cancelled` \| `status:failed` | что произошло         |
| `attempts`        | int                                                                                     | сколько раз пробовали |
| `next_attempt_at` | timestamptz                                                                             | когда пробовать снова |
| `sent_at`         | timestamptz null                                                                        | доставлено            |
| `failed_at`       | timestamptz null                                                                        | сдались               |
| `last_error`      | text null                                                                               | почему не дошло       |
| `created_at`      | timestamptz                                                                             |                       |

Уникальный индекс `(order_id, channel, event_key)`: повторная постановка того же
события не задублирует строку в таблице и сообщение в чате.

## 4. Поток

```
чекаут / оплата / админка
   │  в той же транзакции, что и изменение заказа
   ▼
order_notifications  ← две записи на событие: sheets и telegram
   │  обработчик в api, раз в 10 с
   ├─► Google Таблица: найти строку по № заказа → перезаписать, нет — добавить
   └─► Telegram: created → карточка (сохранить telegram_message_id)
                 status:* → ответ на карточку
```

## 5. Компоненты

- **`lib/notifications/outbox.ts`** — `enqueueOrderEvent(em, order, eventKey)`:
  две записи в той же транзакции, `ON CONFLICT DO NOTHING`. Единственная точка
  входа, её вызывают:
  - чекаут — `created`;
  - `applyPaymentStatus` (вебхук Т-Кассы и сверка) — `status:paid`,
    `status:failed`;
  - ручная смена статуса в админке — `status:*`.
- **`lib/notifications/worker.ts`** — по образцу сверки платежей Т-Кассы:
  раз в 10 с забирает созревшие записи, отправляет,
  отмечает результат. Одна обработка за раз внутри процесса: api — один контейнер, а блокировка строк на время сетевого запроса не нужна. Порядок внутри «заказ × канал»: запись не берётся, пока
  более ранняя запись того же заказа и канала не доставлена и не сдалась.
  Стартует вместе с api, если канал настроен.
- **`lib/notifications/format.ts`** — чистые функции: `sheetRow(order)`,
  `telegramCard(order)`, `telegramStatusLine(order, eventKey)`.
- **`lib/google/sheets.ts`** — сервисный аккаунт: JWT подписывается через
  `node:crypto` (RS256), токен кешируется до истечения. `upsertOrderRow`:
  - читает столбец A листа;
  - если лист пуст, пишет строку заголовков;
  - находит строку по номеру заказа и перезаписывает её целиком, иначе добавляет.

  Режим записи `RAW`. Строка всегда собирается из текущего состояния заказа в
  базе, так что порядок событий для таблицы не важен.

- **`lib/telegram/bot.ts`** — `sendMessage(chatId, html, replyTo?)` через Bot
  API, возвращает `message_id`. Разметка — HTML, пользовательский ввод
  экранируется.

### Колонки таблицы (лист «Заказы»)

|     | Колонка         | Пример                                                                                |
| --- | --------------- | ------------------------------------------------------------------------------------- |
| A   | № заказа        | XM-2026-00042                                                                         |
| B   | Дата оформления | 25.09.2026 14:10 (время московское)                                                   |
| C   | ФИО             | Мария Иванова                                                                         |
| D   | Телефон         | +79123456789                                                                          |
| E   | Почта           | maria@example.com или пусто                                                           |
| F   | Telegram        | @maria или пусто                                                                      |
| G   | Доставка        | ПВЗ NSK1 · Новосибирск, ул. Кривощековская, 15 / Курьер · Москва, Тверская, 1, кв. 12 |
| H   | Состав          | по строке на позицию: `Серная кислота 7% · H2SO4 · 2 × 119 ₽`                         |

Суммы — числами, чтобы по ним можно было считать в таблице.

### Карточка в Telegram

```
🧪 Новый заказ XM-2026-00042 · 25.09 14:10
Мария Иванова · +7 912 345-67-89 · @maria
ПВЗ NSK1: Новосибирск, ул. Кривощековская, 15
— Серная кислота 7% · H2SO4 · 2 × 119 ₽
— Нитрат серебра 1% · AGNO3 · 1 × 349 ₽
Товары 587 ₽ · доставка 504 ₽ · итого 1 091 ₽
Комментарий: после 18:00
Статус: создан
```

Ответы на карточку: `✅ оплачен`, `📦 отправлен`, `✖️ отменён`,
`⚠️ оплата не прошла`. Если карточку отправить не удалось совсем, смена статуса
уходит отдельным сообщением с номером заказа.

## 6. Ошибки и повторы

- **Временные ошибки** — сеть, таймаут, 429, 5xx. Повтор через 1 мин, 5 мин,
  15 мин, 1 ч, 6 ч, затем каждые 6 ч. Через сутки от постановки в очередь — `failed_at`.
- **Ошибки настройки** — лист не найден, нет доступа к таблице, бот не в чате,
  неверный токен. Сразу `failed_at` с понятным текстом в `last_error`, без
  повторов по кругу.
- **Канал не настроен** (нет ключей: разработка, тесты) — обработчик его не
  трогает, записи ждут в очереди и уйдут, когда ключи появятся.
- **Админка:** у заказа видны состояния доставки по каналам и кнопка
  «Отправить ещё раз» — сбрасывает `failed_at`, `attempts`, `next_attempt_at`.

## 7. Безопасность

- В таблицу и чат уходят ФИО, телефон, почта и адрес. Таблица открыта только
  сервисному аккаунту и команде, чат — закрытая группа. Это организационное
  правило: код его не обеспечивает.
- Запись в таблицу в режиме `RAW`: `=IMPORTXML(…)` в имени останется текстом.
- В Telegram весь пользовательский ввод экранируется (`&`, `<`, `>`) перед HTML.
- Секреты — только в `deploy/app.env` (локально `api/.env`), в гит не попадают.
- Перед выкаткой — `/security-review`.

## 8. Настройка (делает владелец)

**Бот:**

1. @BotFather → `/newbot` → токен в `TELEGRAM_BOT_TOKEN`.
2. Добавить бота в рабочую группу, написать в ней любое сообщение.
3. id чата — из `https://api.telegram.org/bot<токен>/getUpdates`
   (`message.chat.id`, у групп отрицательный) → `TELEGRAM_CHAT_ID`.

**Таблица:**

1. Google Cloud Console → проект → включить Google Sheets API.
2. «IAM и администрирование» → «Сервисные аккаунты» → создать → «Ключи» →
   JSON.
3. Содержимое JSON целиком, одной строкой или в base64 →
   `GOOGLE_SERVICE_ACCOUNT_JSON`.
4. Создать таблицу, открыть доступ «Редактор» для почты сервисного аккаунта
   (`…@….iam.gserviceaccount.com`).
5. id таблицы — часть адреса между `/d/` и `/edit` → `GOOGLE_SHEETS_ID`.
   Лист — `Заказы` (переименовать через `GOOGLE_SHEETS_TAB`).

## 9. Тесты

- **Форматы:** экранирование, пустые почта и Telegram, ПВЗ и курьер, бесплатная
  доставка, московское время.
- **Нормализация Telegram покупателя:** с `@` и без, невалидные значения.
- **Очередь:** постановка в одной транзакции с заказом, откат вместе с ним,
  уникальность, порядок внутри заказа и канала, расписание повторов, ошибки
  настройки без повторов, выключенный канал.
- **Google:** подпись JWT, кеш токена, поиск строки → обновление или
  добавление, заголовки на пустом листе, `RAW`. Всё на подменённом `fetch`.
- **Telegram:** карточка, `reply_to_message_id`, отдельное сообщение без
  карточки. Тоже на подменённом `fetch`.
- **Маршруты:** чекаут ставит `created`, оплата — `status:paid`, админка —
  `status:shipped` только из `paid`, поле Telegram на чекауте.
- **Живая проверка** на настоящей таблице и тестовом чате после настройки.

## 10. Вне задачи

- Автоматический «отправлен» по статусам СДЭК — вместе с этапами 4–5
  интеграции СДЭК (`docs/plans/2026-09-23-cdek-delivery-design.md`).
- Обратная синхронизация из таблицы в базу.
- Уведомления покупателю — почта, SMS, Telegram покупателя.
