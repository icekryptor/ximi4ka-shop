# Интеграция с Yandex Commerce Protocol (YCP) — дизайн

Дата: 2026-10-11. Ветка: `claude/yandex-kassa-product-integration-dc0d3f`.
Справочник по протоколу: [`docs/ycp/ycp-api-spec-notes.md`](../../ycp/ycp-api-spec-notes.md).

## Цель

Покупатель в Алисе AI или Поиске Яндекса нажимает «Купить в 1 клик» на товаре Химички. Яндекс вызывает API нашего
магазина, заказ попадает в нашу систему (админка, Telegram, СДЭК) и исполняется так же, как заказ с сайта.

## Принятые решения

| Вопрос           | Решение                                                                                                    |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| Объём            | Полный набор обязательных методов YCP API                                                                  |
| Доставка         | Управляем мы: режим `merchant_ship`, расчёт и пункты выдачи через наш СДЭК                                 |
| Оплата           | Только онлайн (Яндекс Пэй, Сплит). Оплата при получении не поддерживается                                  |
| Товары с кнопкой | Только отмеченные в админке (`ycpEnabled`, по умолчанию выключено)                                         |
| Остатки          | Константа: `in_stock` → 99, остальное → 0. Реального остатка и резерва нет                                 |
| Архитектура      | Новый роутер в существующем API, переиспользование `loadCart`, `packCart`, `quoteDelivery`, outbox-событий |

## Не входит в работу

`GET /order` и `POST /order/delivered` (обязательны только при доставке силами Яндекса), оплата при получении,
автоматические возвраты денег, реальный складской остаток и резервирование, варианты товара, подарок за 3000 ₽
в заказах из Яндекса.

## Архитектура

Новый каталог `api/src/routes/ycp/`. Роутер монтируется в `api/src/app.ts` под `/api/v1`. Caddy уже отправляет `/api/*`
в API, менять его не нужно. Префикс `/api/v1` не должен пересекаться с существующими маршрутами (проверить при
реализации).

### Доступ

- Middleware `requireYcpToken`: заголовок `Authorization: Bearer <token>` сравнивается с `YCP_API_TOKEN` за постоянное
  время (`crypto.timingSafeEqual`).
- Нет токена в env или заголовок неверный: `401 {"error":"Unauthorized"}`.
- Токен придумывает владелец, вносит в `deploy/app.env` и в поле «Токен доступа» кабинета YCP. В репозиторий и чат он
  не попадает.
- «URL для API» в кабинете указывает на `https://ximi4ka.ru` (магазин на апексе; `new.ximi4ka.ru` отвечает 301, POST через редирект не пройдёт). Ожидает ли кабинет корень сайта или
  адрес с `/api/v1` — не подтверждено документацией, проверяется кнопкой «Проверить подключение».

### Формат ответов

Ошибки: `{"error":"<строка>"}`, как в спецификации Яндекса (а не `{error:{code,...}}` нашего публичного API). Свой
обработчик ошибок только для роутера YCP. Время ответа любого метода — до 5 секунд.

## Данные

Одна миграция (`api/src/migrations/<timestamp>-AddYcpFields.ts`, timestamp больше `1790780000000`):

- `products.ycp_enabled boolean not null default false`.
- `orders.source varchar(16) not null default 'site'` (значения `site`, `ycp`).
- `orders.external_session_id varchar(64) null`, уникальный индекс по ненулевым значениям.
- `orders.external_order_id varchar(64) null`.

Сущности `Product` и `Order` и общие типы в `shared/` обновляются. Админка: чекбокс «Купить в 1 клик через Яндекс» в
форме товара; в списке заказов отметка источника «Яндекс».

## Методы

Идентификатор товара в Яндексе = `Product.id` (uuid). Совпадает с `offer id` фида, поэтому режимы
`offers_id_from_merchant_center` true и false обрабатываются одинаково.

### `GET /warehouses`

Один склад. Идентификатор, название, адрес, телефон из env (`YCP_WAREHOUSE_ID`, `YCP_WAREHOUSE_TITLE`,
`YCP_WAREHOUSE_ADDRESS`, `YCP_WAREHOUSE_PHONE`). Самовывоз выключен, `ycp_delivery_options.enabled=false`. Пагинация
`limit/offset` по списку из одного элемента, `total_count=1`.

### `POST /checkout/basket/check`

Для каждого `items[]`: товар ищется по uuid, должен быть опубликован и иметь `ycpEnabled`. Цена за штуку считается
тем же расчётом, что и на сайте (`wholesaleLineTotals`, учёт количества). Ответ: `regular_price` = `priceRub`,
`final_price` = цена за штуку после оптовой скидки, `vat: 0` (магазин НДС не платит; решение владельца 11.10.2026), `warehouses[{id, available_quantity}]` по константе, `dimensions` из упаковки
(`packCart` для одной единицы; вес в граммах, размеры в мм), `characteristics=[]`, `variations=[]`. Неизвестный или
недоступный товар не включается в ответ; если нет ни одного товара, ответ 404 по спецификации. Поле
`is_health_check` на ответ не влияет. Внешних вызовов нет.

### `POST /checkout`

1. Идемпотентность по `session_id`: повтор для существующей сессии → `409` (с `checkout_canceled`, если она отменена).
2. Перепроверка цен и наличия по тем же правилам; расхождение с присланными `regular_price`/`final_price` или нехватка
   наличия → `409` с `actual_inventory`.
3. Создаётся `Order` (`source='ycp'`, `status='pending'`, `externalSessionId`, `paymentProvider='ycp'`), позиции с
   `productSnapshot`, доставка в `deliveryAddress` (пункт СДЭК из `address.pickup_point_id` или адрес курьера),
   `shippingRub` из `delivery.price`. Номер заказа из `nextOrderNumber`, возвращается как `order_number`.
4. Покупатель связывается с `Customer` по e-mail или телефону теми же правилами, что и в публичном checkout.
5. Ответ `201 {"order_number": "XM-2026-000NN"}`.

Подарок не добавляется. Сумма заказа = сумма по позициям + доставка из `delivery.price`.

### `POST /checkout/placed`

Тело: `session_id`, `order_id`, `order_number`, `payment_method`, `online_payment_method`, `acquiring_id`. Query-параметры
(deprecated) принимаются как запасной источник.

- Заказ ищется по `session_id`; нет → `404`; уже отменён → `409`.
- `payment_method='online'`: статус `paid` через `saveOrderWithStatusEvent` — в одной транзакции выпускается событие
  статуса, ставится отправка в СДЭК (`enqueueCdekShipment`) и уведомление в Telegram. Сохраняются `externalOrderId`,
  `paymentIntentId=acquiring_id`.
- `payment_method='on_delivery'`: не поддерживается; заказ не переводится в `paid`, менеджеру уходит уведомление, ответ
  `409` (в кабинете включён режим «Только онлайн-оплата», такие вызовы не ожидаются).
- Повторный вызов для уже оплаченного заказа → `200` без побочных эффектов.
- Платёж принимает Яндекс. В Т-Кассу такие заказы не передаются; провайдер `tbank` и его reconcile их не трогают.

### `POST /checkout/cancel`

`session_id` в query. Заказ `pending` → `cancelled`. Нет сессии → `404`. Заказ уже оплачен: не меняется, `200`.
Резерва нет, снимать нечего.

### `POST /order/cancel`

`order_id` в query. Нет → `404`. Заказ `pending`/`paid` до отправки → `cancelled` через `saveOrderWithStatusEvent`.
Если отправка в СДЭК уже создана или в работе, заказ отменяется в базе, а менеджеру уходит уведомление в Telegram
(ручная отмена в СДЭК и возврат денег). Автовозврат не делается: порядок возврата со стороны Яндекса в документации не
описан.

### `POST /checkout/delivery/options`

Вход: `items[{id, quantity}]` (идентификаторы товаров, как отдаёт `basket/check`), `delivery_target`
(`pickup_point` с `pickup_point_id`, либо `courier` с `locality` и `address`). Цена — через `quoteDelivery`
(тарифы 136 и 137), порог бесплатной доставки как на сайте. Ограничение времени на вызов СДЭК с откатом на запасной
тариф из `lib/shipping/rates.ts`. Срок доставки: период из ответа СДЭК, иначе ориентировочный. В ответе оба ключа,
`options` и `delivery_options`, с одним массивом (схема и пример Яндекса расходятся). У варианта `id` — детерминированный
идентификатор, возвращается в `/checkout` как `ycp_delivery_option_id`.

### `GET /checkout/delivery/pickup_points`

Все пункты выдачи СДЭК. Список по всей России большой, поэтому он собирается фоновой задачей в кэш (память плюс
запасной файл или таблица) и обновляется по расписанию; запрос читает только кэш и режет пагинацию. До первой сборки
кэша отдаётся `500` (Яндекс повторит). Поля: `id` (код пункта СДЭК), `name`, `address`, `is_cash_available`,
`is_card_available`, `working_hours`, `coordinates`, `time_zone`, `display_service_type='cdek'`.

## Фид

В `web/lib/ymlFeed.ts` и `web/app/yml.xml/route.ts`: `param name="is_checkout_enabled"` (true для товаров с флагом, false
для остальных), `weight` (кг) и `dimensions` (см) из данных упаковки. Нужно сверить фид с требованиями Яндекс Товаров
(элементы, не рекомендованные для Товаров: `count`, `vat` и др.; описание без промо-слов). Идентификаторы офферов не
меняются. Условие Яндекса: кнопка показывается только для товаров из фида Яндекс Товаров.

## Тесты

- Тест на каждый метод на одноразовой БД (`TEST_DATABASE_URL`), по образцу `routes/checkout.test.ts`.
- Контрактный тест: формы ответов проверяются по JSON-схеме OpenAPI Яндекса, сохранённой в `docs/ycp/`
  (версия 0.0.14).
- Отдельно: идемпотентность `checkout` и `placed`, 401 без токена, 409 при смене цены, переход `paid` ставит отправку в
  СДЭК и уведомление, отмена оплаченного заказа с созданной отправкой шлёт уведомление, фид содержит
  `is_checkout_enabled`.
- Перед PR: `npm run lint`, `npm run typecheck`, тесты api и web, `npx prettier --check .` в корне.

## Выкатка

Мёрж в `main` выкатывает в прод; мёржим только по явной команде владельца. Порядок:

1. Миграция и код (после команды владельца на мёрж).
2. Владелец вносит `YCP_API_TOKEN` и параметры склада в `deploy/app.env`, перезапускает API.
3. Фид с `is_checkout_enabled` в Яндекс Товарах; владелец отмечает товары флагом в админке.
4. «Проверить подключение», «Обновить склады через YCP», тестовый заказ, публикация в кабинете (до 36 часов).

Перед шагом 3 выполняется `/security-review` (авторизация, данные покупателей, платёжный статус).

## Открытые вопросы и риски

- **Запрещённые товары.** Правила Яндекса исключают «едкие и взрывчатые вещества». Решает владелец флагом по каждому
  товару; при отказе Яндекса флаг снимается без релиза.
- **Округление цены.** Процентные оптовые скидки могут давать нецелую цену за штуку. Правило округления и допуск
  сверки сумм в `/checkout` определяются при реализации по `lib/pricing/wholesale.ts`; расхождение приводит к `409`.
- **НДС.** Магазин НДС не платит, отдаём `vat: 0` (решение владельца). Способа передать «без НДС» в протоколе нет;
  как это ляжет в чек, проверяется на тестовом заказе в кабинете до включения кнопки.
- **Кэш пунктов выдачи.** Объём и способ хранения выбираются в плане; цель — ответ в пределах 5 секунд.
- **Не подтверждено документацией:** повторы и идемпотентность на стороне Яндекса, поведение `404` в `basket/check`
  (может блокировать кнопку по причине `client_404`), формат «URL для API». Проверяется в кабинете на тестовом заказе.
