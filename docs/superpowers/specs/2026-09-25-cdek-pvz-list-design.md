# Выбор ПВЗ из списка на чекауте — дизайн

**Дата:** 25.09.2026. **Статус:** дизайн согласован по частям, ждёт просмотра спеки.
Общий план интеграции — `docs/plans/2026-09-23-cdek-delivery-design.md` (§5.2, §5.3).

## 1. Зачем

Сейчас пункт выдачи выбирают только на карте виджета СДЭК. Если карта не
загрузилась (нет ключа Яндекса, упал CDN, завис скрипт), оформить заказ нельзя.
Владелец считает обязательным выбор из выпадающего списка, как в корзине на
ximi4ka.ru: покупатель вводит город, затем находит пункт в списке с поиском.

**Готово, когда:** на чекауте есть поле «Город» с подсказками СДЭК и поле
«Пункт получения» — список ПВЗ города с поиском по словам; выбор в списке
показывает пункт на карте, «Выбрать» на карте выставляет пункт в списке;
без карты весь путь — город, способ, пункт или адрес курьера, цена, оплата —
проходит до конца.

## 2. Эталон — корзина ximi4ka.ru (Тильда), снято 25.09.2026

- «Город» — поле с подсказками («г Москва, Россия»), под ним «Россия, г Москва».
- Способ доставки — радио «Доставка до ПВЗ СДЭК от 2 дней».
- «Пункт получения» — выпадающий список строк «MSK310, Москва, пр-т Мира» с
  адресом второй строкой («пр-т Мира, 108»), фильтр по подстроке.
- Карты нет. Поиск по подстроке: «Мира» находит, «Мира 108» — «ничего не найдено».

## 3. Решения (согласованы 25.09.2026)

| Вопрос          | Решение                                                                                       |
| --------------- | --------------------------------------------------------------------------------------------- |
| Источник данных | Свои публичные эндпоинты с кешем: подсказки городов и ПВЗ города (подход А)                   |
| Какие пункты    | Только ПВЗ с выдачей (`type=PVZ`, `is_handout=true`). Постаматы — вне задачи                  |
| Поиск           | По словам в коде, названии и адресе: «мира 108» находит «пр-т Мира, 108»                      |
| Курьер          | Свои поля адреса под выбранным городом; курьерская вкладка внутри виджета отключается         |
| Карта           | Под списком. На телефоне свёрнута за кнопкой «Показать на карте», скрипты грузятся по нажатию |
| Без карты       | Список и курьер работают полностью, чекаут не блокируется                                     |

Почему без постаматов: у СДЭК для них свои тарифы (склад-постамат) и
ограничения по габаритам ячеек, а наш тариф 136 и коробки до 40 × 32 × 8 см
туда проходят не всегда. Заказ, который не создастся в СДЭК на этапе 4, хуже,
чем отсутствие постамата в списке.

## 4. Сервер

### 4.1 `GET /api/public/cdek/cities?q=<строка>`

- Проксирует `GET /v2/location/suggest/cities?name=<q>&country_code=RU`.
- `q` — от 2 до 100 символов после обрезки пробелов, иначе 400.
- Ответ: `{ data: [{ code, name, fullName }] }`, до 10 записей.
  `name` — первая часть `full_name` («Москва»), `fullName` — вся строка
  («Нальчик, городской округ Нальчик, Кабардино-Балкария, Россия»).
- Кеш в памяти на 1 час по `q` в нижнем регистре; лимит 60 запросов в минуту
  с IP (существующий `rateLimit`).
- Проверено в песочнице: ответ — массив `{city_uuid, code, full_name, country_code}`.

### 4.2 `GET /api/public/cdek/points?cityCode=<код>`

- Проксирует `GET /v2/deliverypoints?city_code=<код>&type=PVZ&is_handout=true`
  и `GET /v2/location/cities?code=<код>` (центр города для карты).
- `cityCode` — положительное целое, иначе 400.
- Ответ: `{ data: { city: { code, name, location: [lng, lat] | null }, points: [{ code, name, address, location: [lng, lat], workTime }] } }`.
  Из объекта СДЭК берём `code`, `name`, `location.address`,
  `location.longitude/latitude`, `work_time`; остальное (фото, телефоны,
  расписание по дням) не отдаём — в песочнице 142 пункта Москвы весят 282 КБ
  сырыми.
- Сортировка — по `code` (стабильный порядок для поиска и тестов).
- Кеш в памяти на 6 часов по городу; лимит 60 запросов в минуту с IP.
- Ошибка СДЭК — 502 `cdek_unavailable`; пустой список — 200 с `points: []`.

### 4.3 Проверка ПВЗ на чекауте

`POST /api/checkout` с `method: 'cdek_pvz'` сверяет `deliveryPointCode` со
списком города из того же кеша (4.2). Нет такого пункта — 400
`delivery_point_unknown` «Пункт выдачи не найден — выберите другой». СДЭК
недоступен — проверку пропускаем и заказ принимаем: оформление важнее, а
этап 4 покажет ошибку в админке, если пункт действительно закрыт.

### 4.4 Курьер

Контракт `DeliveryDestination` не меняется: `{ method: 'cdek_courier',
cityCode, postalCode?, address }`. `address` собирает клиент: «<город>,
<улица, дом>[, кв. <квартира>]». Индекс — необязательный, 6 цифр.

## 5. Чекаут

### 5.1 Поля и порядок

1. **Город** — комбобокс: подсказки от 2 символов, задержка 250 мс, отмена
   прошлого запроса (`AbortController`), строка «Нальчик · Кабардино-Балкария».
   Выбранный город запоминается в `localStorage` (обёрнуто в try/catch) и
   подставляется при следующем визите.
2. **Способ** — радио «Пункт выдачи СДЭК — N ₽, 2–4 дня» / «Курьер СДЭК — N ₽,
   2–3 дня». После выбора города клиент запрашивает расчёт
   (`POST /api/public/shipping/quote`) для обоих способов: цена ПВЗ зависит
   только от города. Цену по-прежнему считает только сервер; бесплатная
   доставка — как сейчас.
3. **Пункт получения** (ПВЗ) — комбобокс по списку города:
   - строка — «MSK310 · пр-т Мира, 108», второй строкой часы работы;
   - поиск по словам: запрос разбивается на слова, каждое должно встретиться
     в коде, названии или адресе, регистр и «ё/е» не важны, знаки препинания
     игнорируются;
   - показываем первые 50 совпадений; если их больше — строка «Показаны 50 из
     N — уточните запрос»;
   - клавиатура: стрелки, Enter, Esc; разметка `role="combobox"`/`listbox`,
     `aria-activedescendant` — как в `web/components/search/HeaderSearch.tsx`.
4. **Адрес курьера** — «Улица, дом» (обязательно), «Квартира/офис», «Индекс».

Смена города сбрасывает выбранный пункт, адрес курьера не трогает, цены
пересчитываются.

### 5.2 Карта

- Только для способа «Пункт выдачи». На ширине от 768 px — сразу под полем
  «Пункт получения»; уже — кнопка «Показать на карте», виджет и скрипты
  Яндекса грузятся по нажатию.
- `CdekWidget` хранит ссылку на экземпляр виджета и получает
  `city` (координаты центра) и `selectedPoint` (`code` + `location`).
- **Список → карта:** `updateLocation(location, 17)`, затем
  `selectOffice(code)`. Виджет подгружает пункты видимой области с задержкой
  около 500 мс, а `selectOffice` видит только загруженные — повторяем его
  каждые 300 мс до 3 с, потом оставляем карту просто отцентрированной.
  `selectOffice` не вызывает `onChoose`, петли нет.
- **Карта → список:** `onChoose('office', tariff, office)` выставляет пункт
  с кодом `office.code`; если такого нет в списке города (покупатель
  передвинул карту в другой город), выбор отклоняется с подсказкой «Этот пункт
  в другом городе — смените город».
- **Смена города:** `updateLocation(city.location, 10)`.
- Курьерская вкладка в виджете отключена (`tariffs.door = []` и скрытие
  переключателя), чтобы адрес вводился в одном месте.
- **Карта недоступна** — нет ключа, `onError` у `next/script` или 10 с без
  готовности виджета: вместо карты строка «Карта недоступна — выберите пункт
  из списка». Ничего не блокируется.

### 5.3 Данные формы

`choice` становится результатом полей, а не события виджета:
`{ method: 'cdek_pvz', cityCode, deliveryPointCode, address: '<город>, <адрес пункта>' }`
или `{ method: 'cdek_courier', cityCode, postalCode?, address }`.
`validateCheckoutForm` требует город, способ и пункт (или улицу с домом для
курьера) и готовую цену.

## 6. Ошибки

| Ситуация                               | Что видит покупатель                                                |
| -------------------------------------- | ------------------------------------------------------------------- |
| СДЭК не ответил на подсказки городов   | «Не удалось загрузить города» и «Повторить»                         |
| СДЭК не ответил на список пунктов      | «Не удалось загрузить пункты выдачи» и «Повторить»; курьер доступен |
| В городе нет ПВЗ                       | «В этом городе нет пунктов выдачи СДЭК — выберите курьера»          |
| Поиск ничего не нашёл                  | «Ничего не найдено — попробуйте часть адреса или код пункта»        |
| Пункт исчез к моменту оформления (4.3) | Ошибка у поля «Пункт получения», выбор сброшен                      |
| Карта не загрузилась                   | Строка вместо карты, список работает                                |

## 7. Безопасность

- Ключи СДЭК остаются на сервере; новые эндпоинты — только чтение, параметры
  проверяются схемой (`zod`), в СДЭК уходят только `name`/`city_code`/`code`.
- Лимит частоты на оба эндпоинта; кеш снижает нагрузку на договорной ключ.
- В `localStorage` — только код и название города, без персональных данных.

## 8. Тесты

- API: подсказки (обрезка `q`, 400 на короткий, кеш — второй запрос не идёт
  в СДЭК, форма ответа); пункты (параметры запроса в СДЭК, урезанная форма,
  сортировка, кеш, 502 при ошибке); чекаут — 400 на неизвестный код ПВЗ,
  заказ проходит при недоступном СДЭК.
- Веб, чистые функции: поиск по словам («мира 108», «ё», код пункта, лимит 50).
- Веб, компоненты: комбобокс города (задержка, отмена, выбор, клавиатура);
  комбобокс пунктов (фильтр, клавиатура, «уточните запрос»); синхронизация с
  фейковым экземпляром виджета в обе стороны, повтор `selectOffice`; режим без
  карты; курьерские поля и сборка адреса; сброс пункта при смене города.
- Страница чекаута: полный путь без карты до отправки формы.
- Живая проверка в браузере на `localhost` с песочницей СДЭК, ширины 375 и
  1280 px.

## 9. Вне задачи

- Постаматы.
- Сортировка пунктов по расстоянию от покупателя (геолокация).
- Определение города по IP (Тильда так ставит «Париж» из-за языка браузера).
